# Доступы и навыки: что перенести, что проверить

Это карта подключения для Claude, не набор секретов. На том же компьютере исходные проекты и системные CLI остаются на месте. Наличие записи в конфигурации не означает действующий доступ.

## Рабочие возможности

| Возможность | Исходное состояние / точка входа | Действие Claude при настройке |
|---|---|---|
| Claude | CLI установлен, но `auth status` показывает loggedIn=false | Дать Alex выполнить официальный вход; проверить provider, тариф и модели |
| Файлы и Git | Проекты уже на диске; Git установлен | Работать в существующих корнях из реестра; сохранить dirty changes |
| GitHub | `gh` авторизован как inshinav | Проверить read-only доступ к нужному репозиторию; новые tokens не нужны, если существующий доступ работает |
| VPS inshinlab | SSH alias указывает на root@107.189.20.126:22 | Использовать `ssh inshinlab-vps`; проверить hostname/id без изменения сервиса; не выводить ключи |
| Cloudflare | Есть Codex MCP и 11 общих cloud skills; доступ сервисов не проверен | Перенести совместимые MCP или использовать установленный официальный CLI; при необходимости пройти OAuth; проверить нужный account/zone |
| DNS inshinlab | В сохранённом контексте Beget, а не Cloudflare | Проверить текущие NS перед DNS-задачей; не переносить DNS ради настройки Claude |
| Figma | В Codex подключён плагин | Подключить официальный совместимый Claude connector/MCP с отдельным входом; проверить чтение файла; запись проверять лишь по задаче |
| Google Drive / Docs / Sheets / Slides | Доступ идёт через подключённый Codex plugin | Настроить Claude connector или документированный MCP/API; проверить чтение выбранного файла. Нужные права записи проверять отдельно от search/read |
| Браузер | Native инструменты и сессии Codex автоматически не наследуются | Настроить поддерживаемую Claude интеграцию Chrome либо локальную браузерную автоматизацию для тестов; проверить публичную страницу и screenshot |
| Windows-приложения | Codex computer-use runtime привязан к хосту приложения | Найти поддерживаемый Claude механизм, если нужен конкретной задаче; не выдавать файлы навыка за работающий remote control |
| Документы и таблицы | Есть Codex artifact skills, но их runtime может быть специфичным | Использовать поддерживаемые Claude skills/локальные библиотеки; проверить создание и отображение нужного формата |
| Изображения / видео | Есть контент-процессы и внешние провайдеры | Отделить написание промптов от генерации; подключать провайдера только по фактической задаче и разрешённому биллингу |
| Telegram / Apify / Fanvue / WaveSpeed | Параметры находятся в соответствующих проектах/серверном env | Восстановить названия переменных и адаптеры из кода; не экспортировать все токены. Текущие согласия, лимиты и запрет платных генераций сохранить |
| Stitch / Refero | Уже записаны в Claude MCP | Сохранить настройки, проверить scope и соединение; не создавать дубли |
| Codex MCP внутри Claude | Уже существует `codex` | Не использовать для запуска GPT/Codex: запрос Alex — рабочие исполнители Fable/Opus. Избежать цикла Claude→Codex→Claude |
| Автоматизации | Наличие scheduled-tasks каталога не доказывает активные jobs | При необходимости составить read-only список существующих заданий; не переносить расписания и не запускать дубликаты автоматически |

Для Claude login используй официальный [процесс авторизации](https://code.claude.com/docs/en/authentication). Для MCP — [подключение и OAuth](https://code.claude.com/docs/en/mcp). Авторизованные claude.ai connectors и API-key login имеют разные возможности. Не копируй credential store между продуктами.

## Личные навыки Alex

Проверь сначала результат `/import codex --dry-run`; если импорт уже перенёс навык, обнови его адресно, не создавай вторую версию. Команда переносит конфигурацию, инструкции и расширения, но не доказывает перенос аккаунтов или истории. [Официальный импорт](https://code.claude.com/docs/en/commands).

| Исходный каталог | Назначение в Claude |
|---|---|
| `C:/Users/Alex/.codex/skills/alex-content` | Посты INSHIN LAB и личные фотоподписи/Stories MotoLola с сохранением голоса Alex |
| `C:/Users/Alex/.codex/skills/motolola-reels-text` | Reels: overlays, подпись, музыка под взрослую аудиторию США; проверь name в frontmatter |
| `C:/Users/Alex/.codex/skills/motolola-seedance` | Seedance 2.5 Video Edit: анализ клипа, замены, оценка результата и ремонт промптов |
| `C:/Users/Alex/.agents/skills` | Cloudflare, Workers, Agents SDK, Wrangler, Turnstile и связанные процессы |

Подготовь совместимые личные навыки в `C:/Users/Alex/.claude/skills/<name>/SKILL.md`. Вместе с текстом перенеси используемые references/scripts/assets, сохрани относительные пути и авторство. Сначала прочитай содержимое. Убери только ссылки на отсутствующие host-specific инструменты, заменив их реально доступным механизмом; не меняй голос автора, правила проекта и разрешения. Не запускай скрипты навыков просто ради копирования. [Skills Claude](https://code.claude.com/docs/en/skills).

Копируй содержимое по проверенному списку, исключив credentials, env, кеши, зависимости, venv и лишние ZIP. Для каждого навыка запиши источник и дату адаптации. Это рабочая копия: не делай двустороннюю синхронизацию, которая перезапишет исходный Codex skill.

В Claude уже есть 19 design-навыков — полный перечень в `context/local-audit.md`. Сначала просмотри их назначение. Не включай все стили одновременно; выбери нужный по проекту. Не удаляй похожие `design-taste-frontend` и `design-taste-frontend-v1` без сравнения. Глобальные правила Alex имеют приоритет над вкусовыми defaults.

Плагины Codex могут содержать навыки, MCP и собственную среду исполнения. Стандартная структура навыка переносима лишь вместе с нужными зависимостями; копирование plugin cache не устанавливает интерфейс или доступы в Claude. [Структура навыков OpenAI](https://developers.openai.com/plugins/concepts/skills).

## Как выдать доступ без передачи секретов в чат

1. Сначала проверь уже существующий CLI/session и текущий аккаунт без печати секретов.
2. Если есть официальный OAuth, открой его и дай Alex завершить вход/2FA. Не проси отправлять пароль или cookie в чат.
3. Если нужен API token, объясни сервис, требуемые scopes и точное локальное место хранения. Alex вводит его в ожидаемый механизм; в отчёт попадает только факт настройки.
4. Подтверди безвредное чтение. Write-доступ отмечай непроверенным, пока не выполнен уместный разрешённый сценарий.
5. Составь статус по каждой нужной возможности: готово / нужен вход / нужен инструмент / не требуется текущим проектам. Не устанавливай случайный MCP из поиска только ради длинного списка функций.

Личные проекты ChatGPT, встроенный интерфейс Codex, облачные чаты и генераторы медиа не обещаны как точная копия внутри Claude Code. Практический критерий переноса — Claude может выполнить реальные задачи Alex с проверенным результатом.
