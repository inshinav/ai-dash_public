# Claude: настрой рабочую среду Alex и подготовь продолжение его проектов

Это поручение Alex будущей сессии Claude Code. Выполни настройку, а не ограничивайся планом. Пакет подготовлен Codex 28 сентября 2026 года для этого же Windows-компьютера. Сейчас выполняется перенос рабочей среды; развитие продуктов и их деплой — отдельные следующие задачи.

## Результат

Claude работает в существующих проектах Alex, читает его постоянные инструкции и текущие статусы, использует последние доступные Fable/Opus и ultracode, имеет проверенные нужные инструменты и доступы. Сохрани существующую конфигурацию, авторизацию, hooks, MCP, код и незакоммиченную работу. От Alex требуются только действия, которые действительно нельзя выполнить за него: вход, OAuth, подтверждение доверия/биллинга или существенный неразрешённый выбор.

Не покупай подписки, credits и API-баланс, не включай платные дополнительные услуги. Не отправляй сообщения, не запускай платные генерации, не делай push/deploy и не меняй production-данные ради настройки. Эти ограничения не запрещают обычную автономную работу в последующих явно поставленных задачах.

## 1. Прочитай пакет и восстанови исходное состояние

2. Проверь текущее состояние заново: версия Claude, способ установки/входа, выбранная модель, ограничения аккаунта, user/project/local/managed настройки и переменные, влияющие на модели. Выводи только несекретные поля. Не читай и не копируй OAuth tokens, .credentials.json, приватные SSH-ключи и raw истории чатов.
3. На дату аудита Claude `2.1.126`, глобального CLAUDE.md нет, model/effort не заданы, permissions.defaultMode=`bypassPermissions`. Есть PostToolUse hook и MCP codex/stitch/refero. Это исходный снимок, проверь его перед правками.
4. Сначала сохрани резервные копии ТОЛЬКО файлов, которые собираешься менять, в `C:/Users/Alex/.claude/backups/alex-setup-<timestamp>`. Конфигурация может содержать секреты: не включай backup в пакет, Git, отчёт или внешнюю загрузку. Запиши пути без содержимого. Дальше делай точечное объединение; не заменяй весь JSON шаблоном.
5. Учитывай незавершённую работу в Lola Flow. Ни настройка Claude, ни импорт не разрешают reset/stash/clean/смену checkout или редактирование продуктового кода.

## 2. Обновление и нативный импорт

- Если установленная версия не поддерживает пакет, обнови её официальным механизмом `claude update`; требуется как минимум 2.1.280 для указанного Opus 5.5. Не переустанавливай всё с нуля. Старый запущенный процесс не получает новые возможности без перезапуска.
- Если требуется перезапуск, сохрани короткий setup-state.md и точную команду продолжения в этом пакете. После перезапуска продолжи с сохранённого этапа.
- В актуальном Claude сначала используй официальный `/import codex --dry-run`, если команда доступна. Это команда Claude, не PowerShell. Изучи изменения и конфликты, затем перенеси только нужные инструкции, навыки и MCP. Не запускай `/import codex --yes` вслепую и не показывай пользователю сырой вывод с возможными секретами.
- Если команда недоступна текущему клиенту/провайдеру или её нельзя вызвать из агентного контекста, выполни эквивалентный адресный перенос по этому пакету самостоятельно; не блокируй всю настройку ради одной команды меню.
- Нативный импорт конфигурации не доказывает перенос OAuth, всех чатов, файлов облачных проектов или нативных возможностей Codex. Проверяй каждый доступ отдельно.

## 3. Постоянные инструкции и контекст

- Установи подготовленный `CLAUDE.md` в `C:/Users/Alex/.claude/CLAUDE.md`. Если там уже есть инструкции, объедини их и убери дубли, сохранив актуальные требования Alex. Импортированный глобальный текст Codex тоже не должен дублироваться целиком.
- Перенеси реестр и снимки в `C:/Users/Alex/.claude/context`: project-registry.md, projects-inventory.json, chat-index.json, active-projects.md, inshinlab.md. Сохрани даты и ссылки на исходные `.codex/context` файлы. Последнее подтверждённое состояние проекта важнее старого снимка.
- Не загружай все проекты и весь контекст на каждый запрос. Глобальная инструкция должна вести к нужному разделу, а затем к существующему проекту.
- Используй поддержку AGENTS.md актуального Claude; настрой совместное чтение CLAUDE.md и AGENTS.md согласно MODEL-SETUP.md. Если версия не поддерживает нативное чтение, применяй локальный импорт `@AGENTS.md` только там, где файл существует, без циклов импорта.
- Не добавляй абсолютные личные пути в публичные репозитории. Не создавай CLAUDE.md в каждом каталоге автоматически. Локальные адаптеры делай только в реально используемых проектах, исключая их из Git при необходимости.

## 4. Модели и автономность

- Примени `settings.merge.json` как фрагмент, а не как замену файла, с учётом MODEL-SETUP.md. При переносе на другой день сначала сверяй последние Fable/Opus с официальной документацией и доступом аккаунта, затем согласованно обнови точные IDs в профиле и allowlist.
- По умолчанию основная модель — последняя доступная Fable; разрешённая альтернатива — последняя Opus. Для подготовленного снимка это Fable 5.1 и Opus 5.5. Если Alex запустил настройку на Opus (включая `-Model Opus` в запускателе), сохрани Opus основной: перед merge измени только целевой `model` на `claude-opus-5-5`. Не возвращай основную модель на Fable, не проверяй её платным запросом и не включай credits; Fable остаётся разрешённой альтернативой для будущего явного выбора Alex. Не выбирай Sonnet/Haiku/Codex и не запускай через MCP другого LLM для выполнения задач.
- Запускатель передаёт `session-fable.json` либо `session-opus.json` через `--settings`, чтобы ограничения работали уже во время bootstrap. Это сессионные настройки. Не копируй их целиком в user settings: постоянный профиль берётся из settings.merge.json с описанным выше выбором основной модели; проверь и устрани конфликтующие старые env отдельно.
- Основной режим — `ultracode` с xhigh и доступными workflows. Отдельный max используйте только как осознанный режим углублённого reasoning: его нельзя честно выдать за одновременный ultracode. Не добавляй несуществующий `ultra`.
- Ограничь модели главного агента, субагентов, teammates/workflows. Проверь реальные model/effort в новой сессии и задачах. Политику выбранных моделей не переноси на API-модели внутри продуктов Alex.
- Существующий permissions.defaultMode сохраняй; на момент аудита он уже bypassPermissions. Этот пакет не требует переподтверждения уже действующей автономности. Не ослабляй managed policy или системные запреты. При недоступности конкретного действия объясни реальную причину и продолжай разрешённую независимую часть.
- Проверь существующие переменные и frontmatter навыков/агентов, которые могут переопределять model/effort. Не стирай весь env. Изменения значений переменных ОС делай точечно с записью способа восстановления; переменные в settings меняй адресно.
- Не включай автозапуск, Task Scheduler, фоновые бесконечные агенты или recurring jobs: запрос о самостоятельной работе не задаёт расписание. Если уже есть автоматизации, внеси их в реестр без дублирования и без автоматического переноса запусков.

## 5. Проекты и доступы

- Используй `context/project-registry.md`, `projects-inventory.json` и `chat-index.json` для поиска существующих каталогов. Полный домашний каталог Alex не является единым проектом. Не копируй заново все репозитории.
- В каждом найденном активном проекте восстанови корень, инструкции, Git status, отчёт о состоянии, способ запуска и проверок. Не запускай полный CI каждого проекта ради переноса. Удалённые сервисы исследуй адресно по SSH; не скачивай все базы и env.
- SSH, gh и другие уже настроенные CLI обычно доступны на той же машине. Проверяй статус и безвредное чтение. Не переноси приватный ключ в Claude, не выводи токены и не создавай новый доступ без необходимости.
- Подключи нужные сервисы и адаптируй навыки по ACCESS-AND-SKILLS.md. Для OAuth используй официальный вход; личные подтверждения оставь Alex. Авторизованные подключения Codex не считать автоматически доступными Claude.
- Облачные ChatGPT-проекты и только упомянутые чаты пометь отдельно. Не заявляй, что их история перенесена, и не выдавай metadata chat ID за импорт сессии.
- Заполни матрицу: возможность → механизм в Claude → проверка → статус/минимальное действие Alex. Не ставь «готово» только по наличию конфигурации.

## 6. Проверка результата и передача

Выполни применимые проверки из ACCEPTANCE.md. Постоянный профиль проверяй в новой сессии обычного `claude` без `--settings`, `--model` и `--effort`: параметры запускателя не должны скрыть ошибки сохранения. Создай `setup-report.md` рядом с этим файлом: что реально установлено/проверено, что доступно после входа, что недоступно, что изменилось, пути backup и способ отката. Зафиксируй реальные версии, модели, effort и ограничения. Не включай секреты.

Для каждого готового проекта дай короткий путь продолжения: открыть существующую папку → прочитать актуальный статус → выполнить следующий шаг после поручения Alex. Для работающих продуктов проверь, что настройка среды не изменила код и продакшен.

Заверши фактическим результатом и только действительно необходимыми действиями Alex. Не утверждай, что любая задача теперь будет выполняться идеально, что все доступы получены или что фоновые процессы запущены, если это не проверено.
